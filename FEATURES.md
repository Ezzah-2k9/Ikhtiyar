Ikhtiyar mobility feature update
This update adds weather advisories, an optional live-traffic map layer, more conservative Metro availability, trip-goal recommendations, saved destinations, and persistent gamification. The changes are compatible with the existing Flask app and both SQLite and PostgreSQL.
What changed
Weather advisories: Current destination conditions can trigger heat, rain, thunderstorm, wind, and low-visibility guidance. Open-Meteo is the no-key provider; OpenWeather is an optional fallback. The guidance is threshold-based and is explicitly not an official UAE emergency alert. When live weather is unavailable, the page says so rather than displaying a false all-clear.
Traffic map: The calculator has a Show/Hide traffic control and a green-to-red color legend. TomTom flow tiles are requested through an authenticated Flask endpoint so the API key is not placed in browser JavaScript. The colors describe relative traffic flow, not a guaranteed ETA.
Transit availability: A Metro option is shown only when the trip is at least 2 km and both endpoints are within 1.25 km of mapped active Dubai Metro stations. This station-proximity test does not check a live route, transfers, operating hours, or a timetable. Bus and Metro time/fare figures remain labelled estimates.
Route accuracy: Configured OpenRouteService, Geoapify, or TomTom road routes are preferred. If live directions are unavailable, the app identifies distance/time estimates and does not draw a straight-line fallback as though it were a road route. The UI continues to show all available transport choices.
Trip goals: Choose balanced saved preferences, fastest, cheapest, lowest estimated emissions, or shortest distance. Ikhtiyar ranks the available choices for that goal and still shows the rest for comparison.
Saved destinations: Save a place with a personal label such as Home or Office. The resolved coordinates are retained, so the saved place can be reused as either route endpoint without geocoding it again. Up to 25 places may be saved per account.
Gamification: Each recorded trip earns XP; eligible sustainable trips earn more, the first saved trip of a day earns a daily bonus, and consecutive trip days build a streak. Levels advance every 100 XP. The dashboard shows three weekly challenges, progress bars, and rewards. Challenge rewards are persisted and cannot be claimed repeatedly for the same week. Each calculation also issues short-lived signed route quotes; one transport option can be recorded per calculation, and client-edited costs/emissions are ignored.
Render keys and data behavior
No API key is needed for weather advisories. Add `TOMTOM_KEY` in the Render Environment settings to enable the traffic overlay; the same key can also be used for road routes. `ORS_KEY` and `GEOAPIFY_KEY` are alternative routing providers. `LOCATIONIQ_KEY` is recommended for precise private/street-address geocoding. Without it, public OpenStreetMap Nominatim is queried only after a user submits a general landmark search; requests are cached and rate-limited to roughly one per second. The address detector blocks common patterns but is best-effort, not a privacy guarantee. Do not submit private locations without a trusted provider configured. Public geocoding may be unavailable or rate-limited; configure a trusted provider for consistent lookup.
The new tables for saved coordinates, streak/XP state, weekly challenge rewards, and one-use route quote claims are created automatically on app startup. New trip dates use Asia/Dubai local time for streaks and weekly challenges. On Render, the retention of these records depends on the connected PostgreSQL plan; a Free Postgres database is temporary and expires under Render's policy.
Quick manual verification
Sign in and open the calculator. Compare routes using each goal and confirm all available modes remain listed.
Search a Dubai Metro-area trip and a trip with an endpoint well outside Dubai Metro coverage. Metro should only appear in the former case; its fare and time should still be identified as estimates.
Review the destination weather card. For a heat/rain/wind advisory, the message should show the weather source and an advisory disclaimer. If the provider is unavailable, the UI must say that live weather is unavailable.
Add `TOMTOM_KEY` in Render and redeploy, then toggle the traffic layer. Without that key, the control reports that the overlay is not configured.
Save a destination as Home, use it as an origin and then as a destination, and record a trip. The dashboard should show XP, streak, level progress, and weekly challenge progress/rewards.
